# Robot Reel：近期热点与功能路线图

2026-09-13 进展：[Cloth Lab](cloth.md) 已实现软体方向的第一版：在 L40S 上
录制三组独立 VBD 布料弯曲实验，保存原始顶点位置与速度，提供同帧网格对照、
可旋转回放、离线包，以及 OpenUSD／Blender 的逐顶点读回核验。此次只覆盖
固定网格布料；绳索、拓扑变化、材料标定和接触实验仍未实现。

调研日期：2026-09-12。仓库基线：`60299c2`。
P0 的第一版已落地为 [Stress Lab](stress.md)：30 次配对闭环运行、
失败与推理定位、末端轨迹差异、离线包和经过读回校验的 MCAP 遥测。
当前使用已有 hf-libero 的原生光照／相机扰动；完整 LIBERO-plus 适配
及下文其他方向仍是提案。Rerun 原生视图现已提供：导出任一完整配对种子，
同步检查双相机视频、三维末端轨迹、动作和推理曲线，见
[原生工作区与读回核验](telemetry.md#native-rerun-workspace)。

建议把下一阶段的产品定位定为：**可观看、可比较、可复现的物理 AI 实验台**。
首页用具体实验吸引访问者，实验背后的评测记录、数据接口与复现流程服务开发者。

## 最值得先做：VLA Stress Lab

LIBERO-plus 官方接口覆盖物体布局、相机、机器人初始状态、语言、光照、
背景纹理和传感噪声七类扰动，沿用 LIBERO 的观测/动作接口。[6]

第一版固定一个任务、一种策略，以及参考条件和两种原生渲染扰动，
十个配对初始种子，形成 **30 次真实运行的验收集**。结果、失败、执行中断记录、
固定 160 步预算和所有源文件见 [实验说明](stress.md) 与 `stress/summary.json`。
这里只借鉴分条件评测的方向，不将原生扰动称为完整 LIBERO-plus 实现。

每个条件都重新进行闭环推理，让改变后的观测真正进入策略。
Blender 对既有影片的重渲染可作为视觉增强演示，评测结果来自闭环重跑。

首页展示：

- 每个条件的成功次数、实际样本量、置信区间、完成时间和失败类型。
- 成对种子选择与完整运行列表，保留成功、任务失败和执行错误。
- 推理耗时与仿真耗时分别统计，记录测量硬件、精度和批量设置。
- 从指标跳到对应帧，下载实验清单、录像、动作/状态和校验信息。

后续加入 π0.5、GR00T 或其他策略时，先验证任务、动作空间、
观测处理与初始状态的适配。统一报告实际运行结果，不拼接不同上游榜单。

## 共用基础：失败复盘与可交换记录

建议所有新增场景共用一个实验清单，至少记录：

| 类别 | 必需信息 |
| --- | --- |
| 身份与来源 | 实验 ID、Git revision、模型/资产 revision 与哈希、运行配置 |
| 时钟与帧映射 | 仿真时间、采集时间、推理开始/结束时间、源样本与视频帧映射 |
| 观测与动作 | 相机、动作单位/坐标系、执行动作、实测状态、终止观测 |
| 结果 | 成功判定来源、失败/超时/执行错误、有效样本数、缺失数据 |
| 干预与注释 | 人工接管标记、策略原建议、实际执行动作、注释来源 |
| 复用 | 格式版本、媒体/场景文件、校验结果、复现入口 |

先导出 Rerun 可检查的记录与带明确 schema 的 MCAP，再逐步扩展 ROS 2
消息类型、LeRobot 数据集读写。MCAP 是容器格式；各消息 schema、
时间语义和相机/坐标系仍需定义并验证。[3][7]

失败标签优先来自仿真判定、接触、超时和可测量条件。奖励模型或 VLM
可以提供辅助进度/解释，单独保存其来源与输出，保留原始判定和记录。
人工接管场景可以复用 LeRobot 部署流程中的 intervention 标记；
纠正数据的生成与策略改进效果分别验收。[4]

## 多引擎对照怎样做才可信

Genesis 1.4 的归档和原生回放是很好的接入点。[1]
第一版可选择落体接触或双摆等参数可控的简化场景，逐项记录几何、
质量、惯量、摩擦、恢复系数、重力、初始状态、时间步和求解器设置。

每个引擎的轨迹先与自己的原生输出校验，再放到公共时钟上比较。
接触力、冲量等指标需要说明采样与积分窗口。对外定位为“多引擎实验对照”；
不同求解器的轨迹差异是实验结果，不能直接推出某一引擎更接近真实世界。

Genesis 上游的精确回放保证有其支持范围；跨引擎结果和跨机器重新仿真
需要分别验证，不能沿用同一个保证。

## 世界模型：选择真正能输出所需证据的接口

- **LingBot-VA**：LeRobot 文档支持保存预测视频，也有 LIBERO 集成。
  官方给出的推理配置为单卡 24–32 GB，文本编码器默认放在 CPU；
  当前流式评测使用单环境。[8]
- **Cosmos Policy**：官方示例输出动作、未来图像/状态及价值预测，
  适合小规模“预测—动作—实测”对照。README 给出的 LIBERO 基础策略推理
  显存为 6.8 GB；规划等其他配置有额外需求，项目集成仍需实测。[9]
- **DreamZero**：支持联合预测动作和视频，但官方运行说明要求至少两张 GPU。
  适合作为后续算力充足时的扩展。[10]

LeRobot 的 VLA-JEPA 和 FastWAM 在正常推理路径中省去相应的未来想象模块；
它们的名称不能作为推理时必然生成预测视频的依据。[4]
“预测与执行对照”必须从真实导出的预测数据出发。

比较时保留相同条件观测与对应执行动作。预测画面、传感观测、仿真图像
和 Blender 重渲染在数据与页面上明确标识，避免混淆它们的含义。

## Gaussian Splat 与合成数据的边界

Spark 已支持 splat 与 THREE.js 网格结合；2.2.0 的近期优化使其值得作为
新视觉入口研究。[2] 3DGRUT 也提供 USD/PLY 等资产工作流。[11]
第一版应先完成一个扫描场景的尺度、相机标定和机器人坐标对齐，并在
指定桌面/手机设备上实测帧率、首屏体积和内存。

Gaussian Splat 表达外观。物理碰撞、质量与接触来自另行构建和校验的代理模型。
USD 文件所用 schema 与 Blender 的导入支持也应独立验证。

BlenderProc 是成熟的渲染与标注基础，可产生 RGB、深度、法线、分割等输出，
以及 COCO/BOP 等标注。[12] Dataset Studio 在此基础上补充机器人动作、
相机/时间映射与数据集读取验证。生成了一批图像之后，训练收益仍需另做评测。

## 建议的实施里程碑

1. **实验记录与压力测试（已实现第一版）**：固定实验清单；完成一个任务的
   30 次真实运行；提供配对回放、失败／推理定位和完整下载。
2. **生态复用（MCAP、Rerun 已实现）**：已有便携 RRD、内嵌视频、原生布局
   和逐组件读回核验；后续接入 Genesis 原生轨迹。
3. **新增视觉类型**：用一个经过标定的 Gaussian Splat 场景上线 Splat Twin。
4. **预测能力与数据循环**：具备相应 GPU 条件后采集世界模型预测；
   再扩展纠正数据、合成数据与下游训练评测。

建议近期把首页主入口收敛为“机器人任务与压力测试”“多引擎物理实验”
和“实景/预测交互”，已有 Blender 导演与时间雕塑作为各实验的观看和创作入口。
